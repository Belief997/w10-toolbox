# 14_wechat

把消息发到微信「文件传输助手」。**录坐标 → 流程图里改 → 回放**，不做界面识别、不注入进程、不加第三方依赖。

微信 4.x 是 Qt 5.15 应用，UI Automation 只暴露到 `Window / Pane` 两层（实测），
控件一个都读不到 —— 所以只能靠"记坐标 + 模拟点击"。代价是换了客户端版本要重新录。

## 跑起来

```bash
npm run studio        # 起本地编辑器，浏览器开 http://127.0.0.1:7411/
```

编辑器里：

| 操作 | 说明 |
|---|---|
| **整段录制** | 在微信里正常操作一遍（点、粘贴、回车、组合键都算，停顿也会记成「等待」），按 **Esc** 结束，整份流程被这次录制替换。录制期间屏幕右下角有个小浮窗，**实时显示鼠标相对窗口的坐标**和已录步数 |
| **重录**（每一步） | 只重录这一步的坐标：点按钮，然后到微信里点一下 |
| 类型下拉 | 任意一步都能改成 点击 / 粘贴 / 等待 / 按键 |
| ＋ / ↑ / ↓ / ✕ | 在下面插入一步 / 上移 / 下移 / 删除 |
| **演练** | 走完整个流程但**不回车上发**，用来确认坐标 |
| **发送** | 真发 |
| 每步左侧的 ● | 下断点：跑到这一步之前停下，页面上出现 **继续 / 中止**，日志实时刷新（400ms 轮询）。坐标还没调准时尤其有用 —— 停在第 N 步，肉眼看看鼠标是不是落在该落的地方，再放行 |
| **保存 / 加载**（流程库） | 编辑区上方一行：起个名字点**保存**，就存成 `build/flows/<名字>.json`；下拉里选一个点**加载**，当前编辑的流程被它替换（`recorded.json` 也跟着换成这份，刷新页面不丢）。同名保存会先问要不要覆盖 |
| **删除** | 从 `build/flows` 里删掉那个文件 |
| **导出 / 导入** | 导出成 JSON 文件带走（可以进 git、发给别人）；导入任意一份 JSON，`.steps` 数组或者裸数组都认 |

动作一共四种，随便排：

```
点击  相对窗口左上角的坐标
粘贴  剪贴板换内容 + Ctrl+V（中文输入法会吞按键，所以不用打字）
等待  毫秒
按键  单键或组合键：a / enter / tab / ^v / ^+a / %{TAB}
      ^ = Ctrl，+ = Shift，% = Alt，后面跟字母、数字或按键名
```

录制时组合键按当前修饰键状态自动拼：按住 Ctrl 敲 S 记成 `^s`，Shift+2 记成 `+2`。
**Ctrl+V 不单独记** —— 它对应的粘贴已经单独成一步，再记一遍回放会粘两次。

## 命令行

```bash
npm test          # 纯逻辑单测（动作展开、录制文件解析）
npm run record    # 不开编辑器，直接录 3 个点
npm run dry-run   # 按 build/recorded.json 演练
npm run send -- "要发的内容"
```

## 三道闸（都实测触发过）

1. **每次点击前确认微信还是前台** —— 焦点被抢就中止
2. **每次点击前确认那个坐标上最顶层的窗口就是微信** —— 实测有一次坐标被 Microsoft Teams 盖住，
   只校验前台拦不住，必须做这个 hit-test。判据是**同进程**（`GetWindowThreadProcessId` 比 pid），
   不是同 hwnd：微信的联想框 / 搜索面板是单独的顶层窗口（`Qt51514QWindowToolSaveBits`），
   只比 hwnd 会把「点搜索结果」这一步当成都被别的窗口盖住而中止
3. **粘贴的内容由我们设，不用录下来的那份** —— 录制只负责记"这里有一处粘贴"

## 坐标是物理像素

录制（`record.ps1`）和回放（`win.ps1`）**都必须 `SetProcessDPIAware()`**。
少一个，150% 缩放的屏幕上两边差 1.5 倍：录下来的是"虚拟化"坐标，回放用的是物理像素，
点击会整体偏左偏上 —— 这是踩过的坑，两个脚本里都别再删掉那行。

录制文件里存了当时的窗口尺寸：窗口大小一变，面板布局就变了，编辑器顶部会提示
`尺寸变了（录制时 A×B），建议重录`。

## 已知限制

- 换微信版本 / 改窗口大小，坐标要重录（坐标是相对窗口左上角的，挪位置不受影响）
- 发送时微信必须在最前，会抢走焦点 1~2 秒
- 两种发送键都发：先 `enter` 再 `^enter`。微信"发送键"可配成 Enter 或 Ctrl+Enter，
  两种都发能兜住；空消息不会重复发送

## 结构

```
src/win.ps1          窗口 / 焦点 / 点击 / 按键 / 剪贴板 / hit-test
src/record.ps1       通用录制器（click / paste / key / wait）
src/studio-server.js 本地服务 + 静态页
assets/studio.html   流程图编辑器
src/steps.js         动作工厂 + 展开成回放序列（纯函数，有单测）
src/player.js        回放（含两道闸 + 断点钩子 checkpoint）
src/ps.js            PowerShell 调用的薄封装
```

> PowerShell 脚本必须是 **UTF-8 with BOM**，否则 Windows PowerShell 5.1 会按 GBK 解析中文注释直接报语法错。

断点靠三个接口：`GET /api/progress`（active / pausedAt / pausedStep / 实时 logs）、
`POST /api/resume`（放行）、`POST /api/abort`（中止，后面的步骤不跑）。

流程库是 `GET /api/flows`（列表）、`POST /api/flows/save|load|delete`（body 里 `{ name, steps? }`）。
`build/flows/<名字>.json` 就是普通流程文件，格式跟 `build/recorded.json` 一样；
`recorded.json` 始终是"当前正在编辑的那一份"。
